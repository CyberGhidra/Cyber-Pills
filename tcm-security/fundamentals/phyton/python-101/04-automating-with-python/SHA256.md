## 1. Codice Sorgente Completo (`sha256-crack.py`)

Di seguito viene riportato il codice mostrato e completato nell'editor di testo (Sublime Text):

```python
from pwn import *
import sys

if len(sys.argv) != 2:
    print("Invalid arguments!")
    print(">> {} <sha256sum>".format(sys.argv[0]))
    exit()

wanted_hash = sys.argv[1]
password_file = "rockyou.txt"
attempts = 0

with log.process("Attempting to back: {}!\n".format(wanted_hash)) as p:
    with open(password_file, "r", encoding='latin-1') as password_list:
        for password in password_list:
            password = password.strip("\n").encode('latin-1')
            password_hash = sha256sum(password)
            p.status("[{}] {} == {}".format(attempts, password.decode('latin-1'), password_hash))
            if password_hash == wanted_hash:
                p.success("Password hash found after {} attempts! {} hashes to {}!".format(attempts, password.decode('latin-1'), password_hash))
                exit()
            attempts += 1
        p.failure("Password hash not found!")

```

## 2. Spiegazione Dettagliata del Codice Riga per Riga

### Import e Validazione degli Argomenti CLI

* `from pwn import *`
Importa le classi e i metodi di supporto forniti dal framework **pwntools**. In questo progetto vengono utilizzate specificamente:
* La suite di logging dinamico: `log.process()`, `p.status()`, `p.success()` e `p.failure()`, concepite per aggiornare in tempo reale una singola riga di stato a terminale senza saturare il buffer video con milioni di linee di log.
* La funzione integrata `sha256sum()`, che riceve come argomento una sequenza di byte e restituisce l'hash crittografico SHA-256 codificato sotto forma di stringa esadecimale minuscola.


* `import sys`
Importa il modulo di sistema della Standard Library per accedere ai parametri forniti dall'utente tramite la riga di comando (`sys.argv`).
* `if len(sys.argv) != 2:`
Verifica il numero di argomenti passati allo script. `sys.argv[0]` contiene il percorso dello script stesso, mentre `sys.argv[1]` deve contenere l'hash SHA-256 target. Se la lunghezza totale è diversa da 2, il programma avvisa l'utente stampando la sintassi d'uso corretta (`>> <script> <sha256sum>`) e termina l'esecuzione con `exit()`.

### Definizione dei Parametri Operativi

* `wanted_hash = sys.argv[1]`
Memorizza nella variabile `wanted_hash` il valore dell'hash esadecimale da identificare fornito da terminale.
* `password_file = "rockyou.txt"`
Specifica il nome del dizionario da leggere (la wordlist standard *rockyou*).
* `attempts = 0`
Inizializza una variabile contatore a zero per tracciare il numero complessivo di parole testate durante la scansione.

### Logging Dinamico e Gestione dei File

* `with log.process("Attempting to back: {}!\n".format(wanted_hash)) as p:`
Inizializza una sessione di logging avanzato gestita dal context manager `with`. Assegna l'oggetto di stato alla variabile `p`, permettendo di stampare un messaggio introduttivo contenente l'hash target e predisponendo la riga animata sul terminale.
* `with open(password_file, "r", encoding='latin-1') as password_list:`
Apre in lettura (`"r"`) il file del dizionario specificando esplicitamente la codifica `encoding='latin-1'` (ISO-8859-1). Questa impostazione evita l'eccezione `UnicodeDecodeError`, che si verificherebbe leggendo i caratteri binari e non-ASCII presenti in file massivi come *rockyou.txt* con la decodifica predefinita `UTF-8`.
* `for password in password_list:`
Scorre il file iterando riga per riga, mantenendo un impatto di memoria minimo poiché le righe vengono lette sequenzialmente su richiesta.

### Conversione, Hashing e Confronto

* `password = password.strip("\n").encode('latin-1')`
Rimuove il carattere di ritorno a capo (`\n`) presente a fine riga e ricodifica la stringa in un oggetto di tipo `bytes` tramite `.encode('latin-1')`. Il passaggio a sequenza di byte è indispensabile, poiché gli algoritmi di hashing crittografico operano su blocchi di byte grezzi e non su stringhe astratte Unicode.
* `password_hash = sha256sum(password)`
Calcola l'impronta SHA-256 dei byte della password candidata.
* `p.status("[{}] {} == {}".format(attempts, password.decode('latin-1'), password_hash))`
Aggiorna sul terminale la riga di progresso in tempo reale, mostrando il numero progressivo di tentativi (`attempts`), la password decodificata in chiaro e l'hash calcolato.
* `if password_hash == wanted_hash:`
Confronta la stringa dell'hash generato con quella dell'hash cercato:
* Se coincidono, invoca `p.success(...)` per notificare a video il successo, specificando il numero di tentativi impiegati e la corrispondenza univoca tra la parola in chiaro e l'impronta SHA-256.
* Chiude immediatamente il programma con `exit()`.


* `attempts += 1`
Incrementa il contatore dei tentativi prima di passare alla riga successiva della wordlist.
* `p.failure("Password hash not found!")`
Posizionato all'esterno del ciclo `for`, viene eseguito soltanto se l'intero dizionario è stato percorso fino alla fine senza individuare alcuna corrispondenza.

## 4. Note Tecniche sui Meccanismi di Protezione degli Hash

L'esempio mostra come un attacco di dizionario offline operi calcolando l'impronta crittografica di una lista di parole note per identificare il testo sorgente (*preimage*). Questo evidenzia diverse problematiche legate alla memorizzazione delle password:

1. **Assenza di Salting (Cracking diretto e Rainbow Tables):**
Se un hash crittografico viene calcolato direttamente sulla password in chiaro senza un valore casuale aggiuntivo (*salt*), una password identica genererà sempre la medesima impronta. Ciò rende banale l'utilizzo di wordlist e tabelle precalcolate (*rainbow tables*).
2. **Algoritmi Veloci vs Algoritmi Lenti (KDF):**
Algoritmi di hashing generici come SHA-256, SHA-1 o MD5 sono progettati per calcolare rapidamente l'integrità dei dati. Tuttavia, questa velocità costituisce una debolezza nella memorizzazione delle password, poiché consente a sistemi moderni dotati di accelerazione hardware (GPU) di testare miliardi di combinazioni al secondo.
3. **Standard Sicuri per l'Hashing delle Password:**
Nei sistemi di autenticazione moderni si impiegano funzioni di derivazione di chiave lente e computazionalmente onerose (*Key Derivation Functions*), che integrano salting automatico e fattori di costo configurabili (tempo e memoria), quali **bcrypt**, **Argon2** o **PBKDF2**.
